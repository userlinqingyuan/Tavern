# 叙事联动设计：时间线数据化 · 关系网标签 · 档案反向联动

* 日期：2026-09-11

* 范围：单轮实现，纯前端（无构建、无框架、无新依赖）

* 后续：本轮完成后另开第二轮「工程守护」（数据校验脚本 + 可访问性小修），不在本 spec 内

## 1. 目标与非目标

### 目标

1. 时间线事件从 `timeline/index.html` 硬编码迁移到 `data/events.json`，事件中的人名成为可点击的人物引用。
2. 时间线页支持按人物筛选，并支持 `?name=` 外部直达。
3. 关系网的边上显示关系类型标签；单击节点聚焦该人物的关系子图。
4. 档案卡反向显示该人物相关的时间线事件，形成「档案 ↔ 时间线」双向闭环。

### 非目标

* 不新增、不改写任何剧情事件（7 条事件原样迁移）。

* 不修改 `links` 字段与 `related` 原文；关系标签只增不改旧数据。

* 不做图片补全、酒↔人物搭配、年度报告（留给后续轮次）。

* 不做数据校验脚本（第二轮「工程守护」内容），但本设计预留可校验的结构。

## 2. 数据层

### 2.1 新增 `data/events.json`

```json
{
  "events": [
    {
      "date": "2026-08-17",
      "title": "初璃到来",
      "desc": "初璃被带进酒馆，带着行李和一封信。她在角落坐了很久才开口说话。",
      "tags": ["旅客"],
      "people": ["初璃"]
    }
  ]
}
```

* `date`：`YYYY-MM-DD`，排序键（沿用现有从旧到新排序）。

* `title` / `desc`：原文迁移，不改字。

* `tags`：纯分类词，渲染为不可点的灰色小标签（沿用现有 `.tags span` 样式）。

* `people`：人物名字数组，名字必须与 `people.json` 的 `name` 完全一致；渲染为金色可点链接，跳转 `../drinker/?name=<encodeURIComponent(name)>`。群像/设施类事件可为空数组。

7 条事件迁移映射（tags 与 people 的拆分结果）：

| 日期         | 标题       | tags  | people |
| ---------- | -------- | ----- | ------ |
| 2026-08-15 | 酒馆开门     | 酒馆、开业 | 举      |
| 2026-08-17 | 初璃到来     | 旅客    | 初璃     |
| 2026-08-19 | 举的第一次委托  | 委托    | 举      |
| 2026-08-22 | 泠钰的档案归档  | 档案    | 泠钰     |
| 2026-08-24 | 荒泊与白鸢的相遇 | 旅客    | 荒泊、白鸢  |
| 2026-08-26 | 第一次满座    | 酒馆、满座 | （空）    |
| 2026-08-27 | 档案室扩建    | 档案、扩建 | （空）    |

### 2.2 `people.json` 新增 `relations` 字段

与现有 `links`（决定画哪些边）并存；`relations` 只提供边标签，是增量字段：

```json
"relations": [
  { "name": "桃逸佑", "label": "医患" }
]
```

* 无标签的边不需要出现在 `relations` 中。

* `relations[].name` 必须是该人物 `links` 中已存在的名字（一致性由第二轮校验脚本保证；运行时不匹配则忽略）。

* 标签有方向：阮无常 → 桃逸佑是「前监管对象」，反向不成立。

已确认的标签初稿（本轮照此填写）：

| 人物 → 对象   | label |
| --------- | ----- |
| 举 → 桃逸佑   | 医患    |
| 初璃 → 桃逸佑  | 医患    |
| 桃逸佑 → 荒泊  | 生意往来  |
| 桃逸佑 → 举   | 旧识    |
| 芝葵 → 初璃   | 姐姐    |
| 芝葵 → 举    | 好奇    |
| 苏陇客 → 白鸢  | 治愈    |
| 阮无常 → 桃逸佑 | 前监管对象 |
| 陈南恕 → 芝葵  | 一面之缘  |

举 → 荒泊、陈南恕 → 菈提菩 两条有意留空。

### 2.3 边标签的解析规则

边为无向边（沿用现状）。构建边时解析标签：

* 仅一方定义：取该 label。

* 双方都定义（方向不同）：中点显示「甲 / 乙」，甲为按名字排序靠前者一方的视角（确定性规则，避免随机性）。

* 双方都未定义：不绘制标签。

## 3. 时间线页改造（`timeline/index.html`）

1. 删除页内 `events` 常量，改用 `Tavern.loadJSON('../data/events.json')` 加载；加载失败时渲染现有空状态（「时间线上还没有记录」）。
2. 事件渲染：

   * `tags` 维持灰色小标签。

   * `people` 在描述下方新增一行「人物」区域，每人渲染为金色文字链接 `../drinker/?name=...`；样式与页脚链接同体系（新增 `.person-link` 类，金色、下划线偏移）。

   * 人名不在 `people.json` 花名册中时：渲染为灰色不可点文本（容错；第二轮校验脚本负责报错）。花名册通过 `Tavern.loadJSON('../data/people.json')` 获取。
3. 筛选：

   * 页眉（标题与返回链接下方）加一行 chips：`全部` + 所有事件 `people` 去重后的人名（按花名册档案编号排序，与档案页排序一致；未登记人物排末尾）。

   * 选中某人物：只显示 `people` 含该名字的事件；chip 高亮；`location.hash` 不使用，采用 `?name=` 查询参数，并通过 `history.replaceState` 在切换 chip 时同步 URL（不产生多余历史栈）。

   * 页面加载时读取 `?name=` 预选；名字无对应事件时等同「全部」且不报错。

   * 筛选结果为空（理论上不会发生，防御性处理）显示现有空状态文案。
4. 现有 `formatDate` / `escapeHtml` / 排序与视觉样式保持不变。

## 4. 关系网增强（`drinker/index.html`）

### 4.1 边标签绘制

* 在 `buildGraph`/`drawGraph` 现有流程中：边数据增加 `label` 字段（按 2.3 规则从 `relations` 解析）。

* 绘制：边中点绘制小药丸——深褐底（`rgba(20,15,12,.92)`）、1px 金色细边、11px 金字；避免与节点重叠（中点向边的垂直方向微移 6px；标签总数很少，不做防重叠算法）。

* 图例区补一行说明：边上的金字为关系类型。

### 4.2 聚焦子图（交互重分配）

现状：单击节点 = 关闭关系网并滚动到档案卡。新交互：

* **单击节点**：进入聚焦态。被点节点与其一跳邻居节点、相连边正常绘制；其余节点与边以 12% 透明度绘制（不删除，退出聚焦即恢复）。聚焦态下单击其他节点 = 切换聚焦对象；单击当前中心节点 = 退出聚焦（与 ✕ 等同）。

* 聚焦态在图例/头部位置显示工具条：`聚焦：<姓名> ｜ 📄 查看档案 ｜ ✕ 返回全图`。

  * 「查看档案」= 现有跳卡行为（关闭弹窗、滚动、高亮 2s），是移动端主入口。

  * 「返回全图」= 退出聚焦态。

* **双击节点** = 等同「查看档案」（桌面快捷方式）；`handleGraphClick` 中现有的跳转逻辑迁移到 dblclick 与工具条按钮共用的 `focusGraphJump(node)`；单击处理改为切换聚焦。现有 `graphDragMoved` 拖拽守卫对两种点击都生效。

* Esc 两级：聚焦态下第一次 Esc 退出聚焦；非聚焦态 Esc 维持关闭关系网。

* 提示文案 `.graph-tip` 更新为：「单击聚焦关系 · 双击查看档案」。

* 打开关系网时默认为全图态（不记忆上次聚焦）。

## 5. 档案卡反向联动（`drinker/index.html`）

1. 加载流程：`loadPeople` 中通过 `Promise.all` 并行获取 `people.json` 与 `events.json`（均走 `Tavern.loadJSON`），两者就绪后再首次 `render()`；events 失败不阻塞人物渲染（捕获后按空数组处理）。
2. 构建 `eventsByPerson`：`Map<人名, Event[]>`，按日期从旧到新。
3. 卡片模板：在 `${background}` 之后、`<a class="source">` 之前插入「🕰️ 相关记录」区块：

   * 无事件：不渲染任何内容。

   * 有事件：最多列出 3 条，每条 = 灰色日期 + 可点标题（`<a href="../timeline/?name=<本人name>">`，整块统一带参，点击任一条都进入该人物的筛选时间线）。

   * 超过 3 条时末尾显示「全部 n 条 →」（同样链接）。
4. 视觉：沿用 `.note-section` 的小标题风格，新增 `.person-events` 局部样式（细顶边、紧凑行距、金色 hover），不引入新配色变量。
5. 翻页阅读模式（clone 卡片）自动包含该区块；克隆体内链接保持有效。

## 6. 错误处理与降级

| 情况                            | 行为                          |
| ----------------------------- | --------------------------- |
| `events.json` 拉取失败            | 时间线显示空状态；档案卡不渲染相关记录区块；控制台静默 |
| `people.json` 拉取失败            | 时间线人名全部按不可点灰字渲染（不阻塞时间线本身）   |
| 事件人名不在花名册                     | 灰色不可点文本                     |
| `relations.name` 不在 `links` 中 | 画布忽略该标签                     |
| `?name=` 指向不存在/无事件的人          | 时间线按「全部」处理，不报错              |
| 所有 localStorage/JSON 操作       | 维持现有 try/catch 静默策略         |

## 8. 验收标准

1. `data/events.json` 为合法 JSON，恰含 7 条事件；日期、标题、描述与迁移前逐字一致。
2. 9 条 relations 标签内容与 2.2 表格逐字一致；`links` 与 `related` 字段零改动。
3. 时间线：分类标签为灰字；人物名是可点链接且 href 为 `../drinker/?name=<编码>`；chips 筛选正确；`timeline/?name=泠钰` 直达后只显示泠钰相关 1 条且 chip 预选；浏览器前进/后退不产生异常历史。
4. 关系网：医患/旧识/前监管对象等标签出现在对应边中点；单击节点进入聚焦（无关元素淡化、工具条出现）；工具条按钮与双击均可跳到档案卡；Esc 第一次退聚焦、第二次关弹窗。
5. 档案卡：举有 2 条相关记录（开门、第一次委托），泠钰 1 条；无事件人物卡面不出现该区块；点事件链接跳到时间线并带筛选。
6. 六页面内联脚本 Node 编译检查通过；三个 JSON 合法。
7. 浏览器回归无红色 JS 报错；既有功能（翻卡、轮播、收藏、借阅、🎲、翻书、碎片、地图 🗺️ 跳转、品鉴）不回退。
8. 弱网/断 JSON 的降级行为符合第 6 节（可用断 fetch 或临时改名文件验证）。
